# 第7章 结论与展望

> 稿件状态：初稿（2026-08-19）。

## 7.1 研究工作与证据边界

本文围绕传统村落木构建筑可见表观损伤的识别、量化和规划应用，构建了“数据审计—轻量化检测—可测量量化—移动采集—空间台账”的研究框架。现阶段形成的证据可分为三层：第一层是数据审计和 YOLO 基线结果，已在固定 train/valid 协议下完成；第二层是 SAM3、Depth Pro 和 Metric3D v2 的源码级及小规模流程验证，可支持方法链路和敏感性讨论；第三层是 Android/NCNN 与 GIS 的应用原型，已完成源码审计、数据模型和最小点位流程，但尚未完成真机性能和空间统计验证。

因此，本章的“结论”是对已完成证据的归纳，而不是对原研究计划全部目标的宣称。尤其需要指出：test 集尚未用于结果评价；尚未完成的实验不能被表述为无效或有效，最多只能列为后续验证任务。

## 7.2 已完成且可确认的研究结论

### 7.2.1 数据集具有明显长尾与小目标特征

`wood_damage_v1` 的审计结果表明，数据集共包含 2,443 张图像、5,774 个标注框，类别体系覆盖裂缝、深度腐朽、虫害、霉变、表面缺陷和木节等表观类型。标注分布不均衡：`wood_knot` 有 2,388 个框，而 `surface_defect` 仅 71 个框；归一化面积小于 1% 的框占 25.7%。这说明总体指标不能替代逐类和按目标尺度分层的评价，尾部类别和细小目标应作为后续模型选择与现场复核的重点。

数据审计还完成了固定划分、非法标签、重复样本和基本标注一致性检查。上述结果能够支撑数据分布与实验边界的描述，但不等价于对类别语义或工程严重度的最终确认；后者仍需结合专业复核和更细的元数据。

### 7.2.2 轻量化基线能够提供可比较的起点，但瓶颈集中在尾部类和小目标

在固定 valid 协议、单一随机种子下，YOLO11n 的 mAP50 为 0.34931，mAP50-95 为 0.19144；YOLO26n 分别为 0.35303 和 0.19414，二者总体差异较小。基于部署约束和后续可复现性，YOLO11n 被作为后续冻结基线，而不是依据一次实验认定某一模型具有普遍优势。

逐类诊断显示，类别间表现差异明显，尾部类和小目标召回是主要短板。固定置信度与 IoU 条件下，tiny 目标召回约为 0.1096；背景分层诊断中，背景代理越复杂时总体召回呈下降现象。该下降是观察性结果，不能单独证明某一种背景因素具有因果作用；要回答改动是否真正改善背景鲁棒性，还需要完成预注册的 E2/E3 对照和多种子验证。

### 7.2.3 已建立“检测框—提示分割—二维测量”的可复核流程

G0/G1 工作完成了从检测框生成分割提示、批量运行提示分割与深度估计、保存掩膜和测量结果的工程链路。现有小规模核验覆盖 42 个实例，生成 380 个候选掩膜；另有 8 个 YOLO 同类漏检被记录为“检测未召回”，没有被分割模块隐式补齐。边界框扰动实验表明，测量结果会随提示框位置和尺度变化而变化，因此提示框误差必须作为量化不确定性来源记录。

这一结果支持两点：其一，检测输出可以转化为可保存的像素级面积、长度、宽度和方向等观测量；其二，量化流程本身需要报告提示来源、质量标志和敏感性，而不能把单次掩膜直接当作真实边界。由于尚未完成独立人工掩膜、物理标尺或结构检测真值，本文目前不能报告分割精度、厘米级误差、内部腐朽深度或承载力结论。

### 7.2.4 已形成移动巡查与 GIS 应用的设计型成果

Android 项目源码已具备 Camera2 采集、NCNN 推理、CPU/Vulkan 后端接口、照片批处理、结果队列和 PDF 报告等模块，能够支持端侧检测原型的系统设计。与此同时，本文定义了“巡查—照片—损伤事件—构件—建筑”的数据关系和包含模型输出、测量结果、GPS、质量标志及人工复核状态的事件字段，使检测结果具备进入规划台账的接口。

GIS 方面，冻结 train/valid 影像未提取到有效 EXIF GPS；独立目录中仅核验出 2 张带有效 GPS 的原始照片，并成功生成 CSV、GeoJSON 和点位图。这证明了从元数据读取到坐标转换和地图输出的最小链路可运行，但样本量不足以支持损伤热点、空间规律或建筑间差异的统计结论。故本节的应用成果属于流程和数据模型贡献，不是已验证的移动端性能或村落空间规律。

## 7.3 对研究问题的回答

**RQ1：复杂背景下能否稳定识别？** 当前基线能够建立可重复的初筛能力，但逐类差异、尾部类和小目标召回表明“稳定识别”尚未达到可无条件推广的程度。结论应限定为固定数据与 valid 协议下的基线表现。

**RQ2：特征解耦能否提高可解释性？** 本文已经把类别、几何、可测表现、背景干扰和决策状态分列记录，并建立了背景分层诊断框架，因此提高了结果审计和误差定位能力。至于是否带来检测性能的因果改善，需待 E2/E3 完成后再判断。

**RQ3：能否进行可复现量化？** 对检测到的实例，已经能够提取像素级几何量并保留提示敏感性；但绝对尺度、深度和工程阈值映射尚未得到独立真值支持。因此当前回答是“可建立测量流程，尚不能宣称物理量化准确”。

**RQ4：能否服务移动巡查与规划？** 已形成 NCNN 端侧原型的源码基础、事件表和 GIS 图层设计，且完成了两点 GPS 流程核验；但 APK、真机基准、结构化事件导出和足够空间样本尚未形成正式证据。因此当前回答是“应用链路可设计和部分验证，现场可用性仍待实测”。

## 7.4 本文的阶段性贡献

1. **证据门禁下的数据与基线诊断。** 将固定划分、长尾、小目标和背景代理指标纳入同一审计链路，避免用单一总体 mAP 掩盖类别和尺度差异。
2. **测量优先、可追溯的量化框架。** 将检测、提示分割、二维几何测量和不确定性记录分层组织，明确像素观测与工程判断之间的边界。
3. **面向规划巡查的应用数据模型。** 将影像检测结果组织为可关联照片、构件、建筑和空间位置的损伤事件，为人工复核、建筑聚合和修缮复查排序提供接口。
4. **移动端部署约束的研究设计。** 将模型冻结、转换一致性、CPU/Vulkan 后端和端到端性能纳入部署协议，明确了从源码原型走向正式验证所需的证据，而不是以界面 FPS 替代性能实验。

## 7.5 研究局限

第一，数据集来源和类别分布限制了外部推广。当前样本具有明显长尾和小目标特征，部分类别的视觉语义边界仍可能受标注规范影响，且缺少稳定的建筑、构件、拍摄距离和相机标定元数据。

第二，检测结论基于单一种子和已完成的基线实验。E2/E3 的背景干预、训练策略和多种子稳定性尚未完成，背景代理指标只能作诊断，不能被写成因果解释；最终 test 也尚未使用。

第三，量化验证缺少独立真值。当前没有足够人工掩膜来报告分割精度，也没有标尺、深度或结构检测数据来验证厘米级尺寸、内部腐朽和承载力含义。

第四，移动端和 GIS 仍处于原型阶段。现有 Android 资产为 YOLO11s，尚未与论文冻结的 YOLO11n 部署模型统一；没有可追溯 APK、设备信息和 CPU/Vulkan 稳态性能记录。冻结 train/valid 没有有效 GPS，已核验的外部照片仅 2 点，缺少建筑/构件关联，不能进行空间统计或村落尺度推广。

第五，现场应用还涉及隐私、安全和专业责任。原始照片、定位信息和外部服务接口需要进行权限、密钥和脱敏管理；系统输出只能作为巡查筛查和复核线索，不能替代法定保护程序、结构检测或专业鉴定。

## 7.6 后续研究展望

后续工作应按证据依赖关系推进，而不是同时扩大模型、部署和规划结论。

1. **完成检测对照并冻结最终模型。** 在不改变数据划分的前提下完成经批准的 E2/E3，对关键改动进行多种子复现；只有在模型、阈值和部署版本冻结后，才按最终协议使用 test（E8）。
2. **补充分割与物理量真值。** 建立独立人工掩膜评估集，报告 q_dev/q_eval；采集带标尺、相机标定或可验证深度的照片，并以独立物理测量检验深度和尺寸换算。
3. **完成 Android 工程验证。** 将冻结 YOLO11n 转换为 NCNN，核对 PyTorch/NCNN 输出一致性，在指定设备上分别测试 CPU 与 Vulkan 的端到端延迟、P90、稳态 FPS、内存和温升，并补齐结构化事件导出。
4. **恢复可用空间元数据并开展小规模试点。** 通过保留原始 EXIF、人工定位和建筑/构件编号，建立带采样努力记录的照片点和事件图层；空间聚集或建筑比较只能在样本覆盖足够且经过人工核验后开展。
5. **建立专业规则与长期监测闭环。** 由木结构、传统村落保护和规划专业人员共同审查类别语义、复查优先级和标准映射；通过重复巡查记录变化趋势，将模型提示与人工复核和维修结果连接起来。

## 7.7 本章小结

本文目前已经完成数据审计、轻量化检测基线、检测到二维测量的流程验证，以及移动端和 GIS 应用的原型设计。可确认的核心成果是：明确了复杂背景、长尾和小目标对木构表观损伤检测的影响；建立了带敏感性和质量标志的测量链路；提出了可关联照片、构件、建筑和空间信息的损伤事件模型。与此同时，检测改进的因果收益、物理量准确性、Android 真机性能和村落空间规律仍未被证明。后续应以真值、部署基准和最终测试为门槛，逐步把阶段性方法成果推进为可复核的工程与规划证据。
